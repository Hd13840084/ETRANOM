# ETRANOM V1969 — درگاه ثبت امن و تکرارناپذیر درخواست نبرد

## هدف
این نسخه برای مسیرهای موجود Party و PvP یک لایه درخواست با شناسه یکتا اضافه می‌کند. اگر پاسخ شبکه گم شود و همان درخواست با همان `request_id` دوباره ارسال شود، نتیجه قبلی بازگردانده می‌شود و تابع اصلی نبرد دوباره اجرا نمی‌شود.

## فایل مهاجرت
`database/ETRANOM_V1969_COMBAT_RPC_IDEMPOTENCY_GATEWAY.sql` (بازگشت: `database/ETRANOM_V1969_ROLLBACK.sql`)

این SQL باید در Supabase SQL Editor اجرا شود؛ اجرای آن در این بسته انجام نشده است.

## مسیرهای جدید
- `etranom_party_battle_act_v1969`
- `etranom_pvp_action_v1969`
- `etranom_pvp_skill_action_v1969`

این توابع ابتدا هویت و عضویت/شرکت در مسابقه را بررسی می‌کنند، سپس برای درخواست قفل تراکنشی می‌گیرند، رسید قبلی را جست‌وجو می‌کنند و در صورت نبود رسید، RPC اصلی موجود را در همان تراکنش فراخوانی و نتیجه را ثبت می‌کنند.

## چه چیزی تغییر نکرده است
- فرمول آسیب، مهارت‌ها، منابع، نوبت‌بندی و پاداش‌های RPC اصلی بازنویسی نشده‌اند.
- `etranom_party_battle_act`، `etranom_pvp_action` و `etranom_pvp_skill_action` همچنان مرجع اجرای قوانین فعلی هستند.
- مسیر Solo هنوز محلی است و به موتور سرور مرکزی V1968 منتقل نشده است.
- سرویس جاوااسکریپت V1968 هنوز به عنوان موتور واحدِ سرور برای همه حالت‌ها جایگزین RPCها نشده است.
- توابع قدیمی برای سازگاری کلاینت‌های قدیمی حذف یا revoke نشده‌اند؛ بنابراین این نسخه، مهاجرت کامل و اجباری تمام کلاینت‌ها به یک موتور مرکزی محسوب نمی‌شود.

## نگهداری رسیدها
جدول `combat_action_receipts_v1969` فقط از طریق توابع مجاز قابل دسترسی است. تابع پاکسازی `etranom_prune_combat_action_receipts_v1969` فقط برای `service_role` مجاز است و به‌صورت خودکار اجرا نمی‌شود. سیاست پیشنهادی پاکسازی: نگهداری ۱۴ روز.

## مراحل لازم پس از دریافت بسته
1. ابتدا از Supabase نسخه پشتیبان بگیر.
2. SQL بالا را یک‌بار اجرا کن.
3. تست‌های پس از مهاجرت را با دو حساب واقعی انجام بده: Party، PvP حمله، PvP مهارت، ارسال دوباره همان `request_id`، و قطع شبکه پس از ثبت اقدام.
4. اگر هر سه مسیر موفق بود، سپس می‌توان مهاجرت سروری Solo و اتصال واقعی سرویس مرکزی V1968 را طراحی کرد.

## محدودیت تأیید
در این محیط به دیتابیس زنده Supabase دسترسی اجرایی نداشتم؛ پس SQL اجراشده یا تست آنلاین ادعا نمی‌شود. تست‌های این نسخه محلی و ایستا هستند.
