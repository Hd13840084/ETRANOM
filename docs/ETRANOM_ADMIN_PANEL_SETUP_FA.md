# راه‌اندازی ETRANOM Admin Panel روی Cloudflare Pages

این بسته پنل مدیریت را اضافه می‌کند، اما تا زمان تنظیم متغیرها و KV در Cloudflare فعال نمی‌شود. هیچ کلید محرمانه‌ای داخل فایل‌های عمومی قرار ندهید.

## ۱) ساخت KV
1. در Cloudflare Dashboard وارد Workers & Pages → KV شوید.
2. یک Namespace با نام `ETRANOM_ADMIN_KV` بسازید.
3. شناسه Namespace را جایگزین `REPLACE_WITH_CLOUDFLARE_KV_NAMESPACE_ID` در `wrangler.toml` کنید.
4. مطمئن شوید این binding برای پروژه Pages متصل به مخزن ETRANOM نیز در بخش Settings → Functions → KV namespace bindings با نام دقیق `ETRANOM_ADMIN_KV` ثبت شده است. تنظیم `wrangler.toml` به‌تنهایی جایگزین binding داشبورد در همه روش‌های Pages نیست.

## ۲) متغیرهای محرمانه Pages
در Settings → Variables and Secrets برای Production این مقادیر را تنظیم کنید:
- `SUPABASE_URL` = آدرس پروژه Supabase
- `SUPABASE_SERVICE_ROLE_KEY` = کلید محرمانه service_role/secret پروژه (فقط Secret؛ هرگز در GitHub یا مرورگر نگذارید)
- `ADMIN_USER_IDS` = UUID حساب مدیر Supabase؛ برای چند مدیر UUIDها را با کاما جدا کنید.

UUID مدیر را از Supabase → Authentication → Users بردارید. مدیر باید از قبل حساب کاربری داشته باشد.

## ۳) انتشار و آزمون
پس از Push، منتظر Deploy موفق Cloudflare Pages بمانید و سپس `/admin.html` را باز کنید. با حساب مدیر وارد شوید. اگر پیام `admin_not_configured` دیدید، یکی از bindingها یا Secrets تنظیم نشده است.

ابتدا در زمان خلوت، دکمه «بستن فوری بازی برای همه» را آزمایش کنید؛ باید صفحه اصلی بازی پاسخ 503 تعمیرات بدهد و `/admin.html` همچنان در دسترس باشد. سپس با همان پنل «بازکردن مجدد بازی» را بزنید.

## عملیات موجود
- بستن سراسری بازی: فعال‌کردن maintenance در KV؛ صفحات بازی از سمت سرور 503 می‌گیرند.
- بازکردن بازی: پاک‌کردن کلید maintenance.
- مسدودکردن حساب: مدت به ساعت، پیش‌فرض ۷۲۰ ساعت.
- رفع مسدودیت.
- حذف دائمی حساب Auth؛ برگشت‌ناپذیر است.

## محدودیت‌های نسخه اول
- Kick هنوز عمداً غیرفعال است؛ ابطال همه نشست‌های فعال کاربر باید جداگانه با مسیر پشتیبانی‌شده و آزمون‌شده پیاده شود.
- غیرفعال‌کردن ثبت‌نام از این پنل هنوز اضافه نشده است.
- این مکانیزم تعطیلی، درخواست‌های وب را مسدود و کلاینت باز را حداکثر حدود ۱۲ ثانیه بعد از وضعیت maintenance خارج می‌کند؛ اتصال Realtime ممکن است تا اجرای خروج کلاینت باز بماند.
- حالت maintenance تا وقتی KV binding و Secrets تنظیم نشوند فعال نمی‌شود. ابتدا روی محیط آزمایشی بررسی کنید.
- عملیات حذف حساب می‌تواند با سیاست‌های FK/داده‌های بازی درگیر شود؛ پیش از استفاده واقعی، از دیتابیس پشتیبان بگیرید و رفتار حذف وابستگی‌ها را بررسی کنید.
