# ETRANOM V2022 — بسته نهایی پنل Owner

این بسته بر اساس خروجی یک‌ردیفی واقعی Supabase که در گفتگو پیوست شد تهیه شده است. آن خروجی شامل ۱۰۶ تابع/RPC، ۳۸ سیاست RLS، ۹ تریگر و ۴۶ جدول دارای RLS بود.

## محتوای بسته

1. `ETRANOM-V2022-OWNER-FINAL.sql` — سخت‌سازی ACL توابع Trigger و محدودسازی اجرای تابع زمان‌بندی انقضای بازار به نقش‌های سرور. این فایل منطق خریدوفروش، انتقال دارایی، نبرد، Party، PvP و ذخیره بازی را بازنویسی نمی‌کند.
2. `ETRANOM-V2022-FINAL-AUDIT-ONE-ROW.sql` — ممیزی کامل یک‌ردیفی؛ شامل شمارش‌ها، مجوزها، SECURITY DEFINER، search_path، تعریف توابع، RLS، Policyها، Triggerها، وضعیت Owner و فقط شکل کلیدهای سطح اول save_data (بدون مقادیر ذخیره بازیکنان).

## ترتیب اجرا

1. از دیتابیس Supabase یک Backup/Point-in-Time Recovery در دسترس داشته باشید.
2. فایل `ETRANOM-V2022-OWNER-FINAL.sql` را با نقش postgres در SQL Editor اجرا کنید.
3. در همان خروجی، Query پس از COMMIT باید صفر ردیف برگرداند. هر ردیف یعنی یک بررسی ناموفق؛ در این حالت ادامه ندهید.
4. فایل `ETRANOM-V2022-FINAL-AUDIT-ONE-ROW.sql` را اجرا و خروجی CSV/JSON یک‌ردیفی را نگه دارید.
5. پنل Owner و بازی را با حساب Owner و یک حساب بازیکن عادی آزمایش کنید: مشاهده پرونده، patch محدود، کیف/تجهیزات، بن/رفع بن، عملیات Guild/Party/PvP، بازار و خزانه.

## نتیجه بررسی منبع و محدوده نهایی

- در ممیزی ارائه‌شده، پنج تابع دارای ACL مستقیم برای `anon`/`PUBLIC` از نوع Trigger handler بودند: `create_etranom_player_profile`, `etranom_archive_game_save_v1643`, `etranom_global_chat_prepare_message`, `etranom_owner_role_guard_v11`, `etranom_sync_player_profile_from_save`. اجرای مستقیم کلاینت برای آنها بسته می‌شود؛ اجرای خود Triggerها باقی می‌ماند.
- `etranom_market_expire()` فقط برای `postgres` و `service_role` باقی می‌ماند.
- در خروجی جدول‌های ارسالی، جدول مستقل مشخصی برای companion/Legion دیده نشد. برای جلوگیری از خراب‌شدن ساختار Save، این بسته مقادیر JSON یا مسیرهای نامعلوم را حدس نمی‌زند؛ ممیزی نهایی فقط نام کلیدهای سطح اول و نوع داده آنها را گزارش می‌کند. اگر همراهان در `game_saves.save_data` باشند، ساختار واقعی‌شان از همین گزارش قابل تعیین است.

## معیار اعلام نهایی

این نسخه از نظر فایل و SQL، نسخه نهایی تحویل است؛ اما «نهایی و تأییدشده روی محیط زنده» فقط وقتی است که اجرای migration بدون خطا انجام شود، Query assertion صفر ردیف بدهد، ممیزی نهایی همه checkها را true نشان دهد و تست‌های دستی بالا موفق باشند. این گفتگو دسترسی اجرایی به پروژه Supabase ندارد و نمی‌تواند به‌جای مالک پروژه ادعای اجرای زنده یا تست بازی کند.
