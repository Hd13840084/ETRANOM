# مرحله دوم آنلاین‌سازی ETRANOM — ساخت کلاینت Party

این بسته شامل پیاده‌سازی سمت مرورگر سیستم Party است. هیچ تغییری در پایگاه داده یا اسکریپت‌های SQL این مرحله اعمال نشده است.

## فایل‌های کلاینت
- `systems/party/party.js`: راه‌اندازی سیستم، اتصال Supabase RPC، بازیابی وضعیت و مدیریت نشست کاربر.
- `systems/party/party-config.js`: سقف ۴ عضو، حداقل ۲ عضو برای شروع و پنج منطقه مجاز.
- `systems/party/party-manager.js`: ساخت/ترک/انحلال گروه، آمادگی و مدیریت اعضا.
- `systems/party/party-invites.js`: ارسال، پذیرش، رد و لغو دعوت.
- `systems/party/party-sync.js`: دریافت رویدادهای Realtime برای گروه و اعضا.
- `systems/party/party-combat.js`: انتخاب منطقه، بررسی آمادگی، شروع و پایان نشست.
- `systems/party/party-ui.js`: رابط گروه، فهرست اعضا، دعوت دوستان، مدیریت رهبر و دعوت‌نامه‌ها.
- `systems/party/party.css`: استایل رابط Party.

## پیش‌نیازهای سمت پروژه
1. صفحه ورود باید Supabase client را با نشست معتبر بسازد.
2. `window.lib.getSocialOverview()` باید فهرست دوستان را با فیلد `user_id` برگرداند تا دعوت مستقیم از رابط فعال باشد.
3. فایل `index.html` فایل CSS مربوط به Party را بارگذاری می‌کند.
4. RPCهای مورد استفاده باید دقیقاً مطابق امضاهای موجود در `database/party.sql` در Supabase نصب شده باشند.
5. Realtime باید برای جداول `parties` و `party_members` فعال و مجاز باشد؛ تنظیم آن در مرحله SQL بررسی می‌شود.

## محدوده این تحویل
- کد کلاینت و رابط Party تکمیل شده است.
- SQL تغییر نکرده و در این مرحله اجرا یا دوباره نصب نمی‌شود.
- هنوز آزمایش زنده چندحسابی انجام نشده؛ این مورد پس از بررسی SQL و تنظیمات Realtime انجام می‌شود.
- `finish_party_session` در SQL فعلی فقط وضعیت نشست را ثبت می‌کند و پاداش بازی توزیع نمی‌کند؛ توزیع پاداش خارج از محدوده این کلاینت است.

## نصب در مخزن
محتویات ZIP را در ریشه مخزن جایگزین/ادغام کنید و ساختار `systems/party/` را حفظ کنید. نقطه ورود انتشار `index.html` است.
