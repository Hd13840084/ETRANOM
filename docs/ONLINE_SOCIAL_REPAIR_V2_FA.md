# اصلاح آنلاین چندبازیکنه ETRANOM — نسخه ۲

## چه چیزی اصلاح شد؟

1. لایه نقشه دیگر کانال Realtime دومی با همان topic یعنی `etranom:global-presence` ایجاد نمی‌کند. این کانال فقط یک‌بار توسط `ETRANOMPresence` ساخته می‌شود و آواتارهای نقشه همان وضعیت Presence را مصرف می‌کنند.
2. وضعیت Presence پس از همگام‌سازی، ورود و خروج نشست‌ها از طریق رویداد داخلی به لایه نقشه اعلام می‌شود.
3. لایه نقشه همچنان موقعیت، نام، سطح و کلاس بازیکن را از metadata حضور می‌خواند؛ آواتارهای دوست/هم‌انجمنی/عادی از همان داده مشترک ساخته می‌شوند.
4. مهاجرت `database/online_social_repair_v2.sql` تابع محدود `etranom_are_friends` را برای بررسی رابطه دوستی ایجاد می‌کند. این تابع فقط بررسی خواندنی انجام می‌دهد و برای جلوگیری از ردشدن ناخواسته پیام به‌علت RLS جدول friendships، با `SECURITY DEFINER` و `search_path` خالی اجرا می‌شود.
5. سیاست درج پیام خصوصی به فرستنده احراز هویت‌شده، گیرنده متفاوت و دوستی ثبت‌شده محدود است. سیاست خواندن پیام فقط فرستنده و گیرنده را مجاز می‌کند.

## ترتیب نصب الزامی

1. از Supabase و مخزن GitHub نسخه پشتیبان بگیر.
2. در Supabase → SQL Editor، کل فایل `database/online_social_repair_v2.sql` را اجرا کن.
3. اگر SQL با خطای نبودن جدول/ستون `friendships.user_low` یا `friendships.user_high` متوقف شد، ادامه نده و متن کامل خطا را بفرست؛ ساختار واقعی جدول دوستی باید با migration هماهنگ شود.
4. پس از اجرای موفق SQL، فایل‌های این ZIP را در ریشه مخزن جایگزین کن و روی شاخه `main` منتشر کن.
5. Cloudflare Pages را تا پایان deploy صبر کن و سایت را با دو حساب مستقل در دو مرورگر آزمایش کن.

## آزمون‌های لازم با دو حساب

- هر دو حساب وارد یک منطقه شوند؛ آواتار هرکدام باید برای دیگری دیده شود.
- حرکت یکی از حساب‌ها باید موقعیت آواتارش را برای دیگری تغییر دهد.
- بازیکن دوست باید هاله سبز، هم‌انجمنی طلایی و بازیکن عادی سفید/خاکستری داشته باشد.
- پیام خصوصی فقط بین دوستی‌های تأییدشده ارسال شود.
- دریافت و ارسال پیام در هر دو جهت بررسی شود.
- خروج یک حساب نباید نشست حساب دیگر را قطع کند.

## محدودیت تأیید

آزمون‌های محلی JavaScript اجرا شده‌اند؛ اتصال زنده به پروژه Supabase و اجرای migration روی پایگاه داده کاربر از این محیط ممکن نیست. بنابراین موفقیت نهایی باید پس از اجرای SQL و آزمایش دو حساب تأیید شود. این بسته تضمین نمی‌کند خطاهای مستقل سایر زیرسیستم‌ها مانند انجمن‌ها، بازار یا گروه‌ها نیز رفع شده باشند.
